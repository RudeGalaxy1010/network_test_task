# NetworkMessages

Небольшой Unity-проект с сервисом адресной отправки сетевых сообщений поверх
[Mirror](https://github.com/MirrorNetworking/Mirror).

## Задача

Стандартный механизм сообщений Mirror отключает клиента, если на нём нет
обработчика для полученного типа сообщения. Реализация добавляет слой подписок:
сервер отправляет сообщение только тем клиентам, которые явно подписались на
его тип. Исходный код Mirror при этом не изменяется.

## Как это работает

1. Клиент вызывает `Subscribe<T>()` и регистрирует обработчик сообщения.
2. Клиент отправляет серверу `MessageSubscriptionRequest` с ID типа сообщения.
3. Сервер хранит подписки отдельно для каждого `connectionId`.
4. `SendToSubscribers<T>()` отправляет сообщение только подходящим клиентам.
5. При последней отписке или отключении клиента его подписки удаляются.

Для демонстрации используется `HelloMessage` с текстом `Hello Client!`.

## Запуск демо

1. Открыть проект в Unity `2022.3.62f3`.
2. Открыть сцену `Assets/Scenes/SampleScene.unity` и нажать **Play**.
3. В Mirror HUD нажать **Start Host** либо запустить сервер и отдельный клиент.
4. На клиенте нажать **Subscribe HelloMessage**.
5. На сервере нажать **Send Hello to subscribers**.
6. На клиенте появится `Received: Hello Client!`.

Сцена использует Telepathy Transport, адрес `localhost` и порт `7777`.
В режиме Host сервер и клиент работают в одном экземпляре Unity. Для проверки
раздельного подключения можно запустить второй экземпляр проекта или билд.

## API

```csharp
clientMessages.Subscribe<HelloMessage>(OnHelloMessage);
serverMessages.SendToSubscribers(new HelloMessage
{
    Text = "Hello Client!"
});
```

Основные точки расширения:

- `INetworkMessageClientService` — подписка и отписка обработчиков на клиенте;
- `INetworkMessageServerService` — отправка сообщений подписчикам;
- `MessageSubscriptionRequest` — служебное сообщение синхронизации подписки;
- `HelloMessage` — пример пользовательского сообщения.

Оба сервиса зарегистрированы в Zenject через `NetworkInstaller` как singleton и
создаются без отложенной инициализации.

## Структура

```text
Assets/App/Network/
├── Api/   # интерфейсы сервисов и типы сообщений
├── Impl/  # реализация подписок, DI-регистрация и демо-компоненты
└── Tests/ # Edit Mode и раздельные client/server Play Mode тесты
```

## Тесты

Тесты запускаются через **Window → General → Test Runner**:

- **Edit Mode** проверяет защиту от использования сервисов до инициализации;
- **Play Mode (Client)** проверяет подписку, отписку, повторную подписку,
  несколько обработчиков и доставку разных типов сообщений;
- **Play Mode (Server)** проверяет доставку подписчикам, фильтрацию по типу,
  очистку подписки при отключении клиента и отсутствие доставки после отписки.
